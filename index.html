Project 01 / 03
Evolutionary Build Story

Aurora — From a Telegram Bot to a Self-Reflecting Second Brain

Aurora didn't start as an over-engineered architecture diagram. It evolved organically step-by-step to solve real problems I ran into:

1

The Spark: Placement Prep & Health Tracking

I needed a fast, zero-friction way to track my daily placement preparation schedule and health metrics. I started by wiring up a simple Telegram bot with Gemini as the brain so I could message it from anywhere.

2

"Why not a dedicated app & real backend?"

A Telegram bot had UI limits. I built an installable Android app (Kivy) for 1-tap mobile access, then realized it needed past conversations as persistent context. So I architected a standalone FastAPI backend with JWT user authentication.

3

Hardening with PyTest, Docker & CI/CD

Having a live backend meant things could break. I wrote test suites with pytest, containerized the whole stack with Docker Compose, and set up a GitHub Actions CI/CD pipeline that automatically tests every commit and deploys cleanly to AWS EC2.

4

The Knowledge Graph & Obsidian Visualizer

I wanted Aurora to remember long-term facts, goals, and study briefs without dumping huge unstructured chat histories into LLM prompts. I structured the memory into an SQLite Knowledge Graph + FTS5 full-text search, and even wrote an Obsidian KG viewing script to visualize my evolving second-brain network as interactive graph nodes.

5

Self-Reflective CRAG + Live Search Fallback + Multi-LLM

Since LLMs have knowledge cutoffs, I built a Corrective RAG (CRAG) pipeline with LangGraph: if facts aren't found in the Knowledge Graph or uploaded documents, it self-evaluates and automatically executes a live DuckDuckGo web search. Finally, I added on-the-fly model switching between Gemini, OpenAI, Claude, and local private models (llama.cpp/Ollama).

The Edge AI Experiment

Lottery Ticket Hypothesis: Trimming 74% of a Neural Net for Farm Robots

What started as an exploratory course project turned into a systematic investigation of where Lottery Ticket theory meets edge deployment reality:

1

The Origin & Dense Baseline

I originally picked this as a course project because a friend convinced me it would be easy. I designed WeedCNN (25,974 parameters) for bounding-box detection on an agricultural dataset, achieving a 96.15% dense validation baseline at 50.7 KiB (FP16).

2

Pruning Exploration: One-Shot vs. IMP

I tested simple one-shot magnitude pruning from 10% to 90%, discovering an extreme sparsity ceiling where 99% one-shot collapsed (~45% Acc). Moving to Iterative Magnitude Pruning (IMP) across 7 rounds uncovered sparse winning sub-networks matching 97.40% validation accuracy at 73.8% sparsity.

3

Weight-Reset Strategy Ablation (Frankle & Carbin LTH)

To determine if sub-networks genuinely required their original initialization, I ran an ablation across three reset strategies: Original Init (W0), Random Re-Initialization (Wrand), and Late Reset (Wk=5), proving that late rewinding provided the highest round-over-round training stability.

4

Practical Edge Deployment: Quantization & Distillation

Because unstructured sparsity doesn't automatically reduce memory without custom hardware kernels, I benchmarked it against real deployment techniques: Dropout Regularization (0.2 optimal), Knowledge Distillation (soft-target student acceleration), and INT8 Post-Training Quantization, compressing the deployable binary to a tiny 25.37 KiB ready for battery-powered farm robots on Raspberry Pi.

Environmental Telemetry & XAI

AeroSense.AI — Explainable Atmospheric Telemetry & AQI Microservice

An end-to-end Machine Learning web service and developer REST API analyzing atmospheric pollutant telemetry (PM2.5, PM10, NO2, CO, SO2, O3) across 26 major urban monitoring stations (29,531 records) with Explainable AI (XAI):

1

Multi-Station Sensor Ingestion (29,531 Records)

Aggregated real-time continuous atmospheric telemetry across 26 major urban sensor stations in India, monitoring 6 critical pollutants: PM2.5, PM10, NO2, CO, SO2, and O3.

2

Mitigating Selection Bias: Why Not dropna()?

Environmental sensors intermittently go offline during routine calibration or severe smog spikes. Discarding rows with dropna() would purge >60% of real historical records and erase rare Severe crisis events. Because pollutant curves follow right-skewed log-normal distributions, I implemented Median Imputation to prevent extreme peak distortion while preserving critical crisis telemetry.

3

Stratified RandomForest & Continuous XAI Engine

Implemented stratified 75/25 partitioning to preserve minority severe-smog class distributions. Trained an ensemble RandomForestClassifier coupled with an Explainable AI (XAI) engine that computes continuous sub-indices and dynamic feature importance to explain *why* an AQI spike occurred.

4

High-Throughput REST API (<15ms) & PyTest Suite

Serialized the model pipeline and deployed a lightweight Flask JSON microservice (POST /api/predict) with sub-15ms inference latency suitable for resource-constrained IoT gateways, backed by 12 automated unit and integration tests in pytest.
